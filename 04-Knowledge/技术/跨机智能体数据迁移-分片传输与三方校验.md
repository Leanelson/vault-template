# 🔧 跨机智能体数据迁移：分片传输与三方校验

> 场景：把**别人机器上**的智能体全量数据（会话历史 + 项目 + 源码）经**中转机**搬回本机。
> 全程只能**用聊天消息**下达指令（无法发文件），通道是低带宽 frp 隧道（实测 0.25–0.4 MB/s）。

## 🧭 拓扑

本机 → frps → 中转机（Windows，`cloud_user@…:6679`）；数据源是第三台机器上的临时智能体，
它**主动 push** 到中转机，本机再 pull。**方向单一、每段可独立校验**是关键设计。

## 🔑 四条主线

1. **一次性密钥协议**：对方不信任外部私钥与凭据模板，改为**它自己生成密钥对**、只把公钥交给我，
   我登记到 `administrators_authorized_keys`；用完**立即撤销并实测拒绝**。
2. **分片**：单包 ≤30MB（`split -b 30M`），命名 `b4.aa … b4.bs`。低带宽下分片让**断点恢复**成为可能。
3. **每条命令只传 ≤10 片**（≈23 分钟）。对方环境有**命令超时**：一次把 45 片塞进一条 `for` 循环，
   跑到 ~55 分钟被整条杀掉，第 26 片只写了一半（4.2MB/30MB）——**这是本项目最大的一次返工来源**。
4. **三层哈希对齐**：对端原文件 → 中转机合并后 → 本机落袋后，三者 sha256 必须一致；
   合并后再 `tar -tzf` 数条目（如 56,790 条）作为第二重证据。

## ⚠️ 踩过的坑（按代价排序）

| 坑 | 现象 | 正解 |
|---|---|---|
| 命令超时 | 一条命令跑 45 片，55 分钟被杀，断在半片 | 每命令 ≤10 片，配 `until scp …; do sleep 5; done` 重试 |
| 对方后台进程被回收 | `nohup` 循环、`up.log` 空、切片只剩 57M/75M | 放弃后台常驻，改成**前台一条片一条命令** |
| 传输无断点 | 重传必须整片重来 | 分片粒度即恢复粒度；半片用同名覆盖重传即可 |
| `.NET 版本低` | `[IO.File]::AppendAllBytes` 报 `MethodNotFound` | 用 `FileStream` + `Append` 循环替代 |
| 中文脚本乱码 | PS1 含中文被按 GBK 解析 → ParserError | **脚本纯 ASCII**，或存成 **UTF-8 带 BOM** |
| ssh 吃掉脚本 stdin | 管道喂 bash 脚本时卡住 | `ssh -n` |
| cmd 嵌套引号 | `find /c "x"` → `FIND: 参数格式不正确` | 别在 ssh→cmd→PS 里套三层引号；改**部署 .ps1 再 `-File` 执行** |
| 自建脚本路径拼接 | `LOG=a/b.log` 又写 `>> a/$LOG` → 重定向失败，rsync 一条没跑 | 相对路径只**拼一次** |
| 磁盘 I/O 浪费 | 哨兵每轮合并 750MB 半成品 | 哨兵先**只计数**，片齐（连续两轮稳定）才合并 |
| 误判损坏 | 对方以为非 30M 的片是坏的 | 首片/末片本来就非整片：`ba.aa`/最终余数**属正常** |

## 💡 两个高价值发现

1. **软删除会话可救回**：OpenClaw 的会话是 `*.jsonl.deleted.<时间戳>`，删除只是改名——
   打包时一并带回，等于**抢救了 53 个本会永久消失的会话**（有几个是迁移当天才删的）。
   迁移任何 agent 的数据前，**先找 `.deleted.` / `.reset.` 残留**。
2. **活跃度不看 git 看 cron**：该机 git 多为一两次提交的快照，但 cron 一直跑到迁移当天——
   判断"这台机器还活着吗"要看**定时任务与运行日志**，不是提交记录。
