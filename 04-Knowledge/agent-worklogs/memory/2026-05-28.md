# 2026-05-28

## frp HTTPS隧道调试（深夜 23:00-00:30）

### 问题
用户想在 `www.zlh1.com` 上启用 HTTPS，需要 frp 在 80 端口做 HTTP 虚拟主机。
之前 nginx 占了 80 端口导致 502，停掉 nginx 后 frp 也无法接管 80。

### 根因
frps 配置文件 `/etc/frp/frps.ini` 里有：
- `vhostHTTPPort = 80` / `vhostHTTPPort = 443` / `vhostHTTPPort = 28080` 三行重复
- frp 0.51.3 INIParser 读最后一个值 → 实际是 28080，80 和 443 被覆盖
- frps 以普通用户运行，没有 root 权限无法绑定 <1024 端口

### 解决方案（进行中）
1. 删除了 `vhostHTTPPort = 28080` 那行
2. frp 0.51.3 正确的键名是 `vhostHTTPPort`（驼峰），不是 `vhost_http_port`（下划线）
3. iptables 做了 80→28080 转发作为 fallback
4. 需要 frps 绑定到 80 端口才能生效

### 当前状态
- frpc 已更新为 HTTP 代理类型（`[web-zlh1]` section）
- frps 配置已清理为：
  ```
  vhostHTTPPort = 80
  vhostHTTPSPort = 443
  ```
- 已知 frps 端口 8787 正常工作（有日志输出）
- 等待用户确认 frps 重启后是否监听 80
