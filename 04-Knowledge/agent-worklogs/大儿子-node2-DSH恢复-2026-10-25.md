## 一、结论：不是 WSL / Docker

- 大儿子上 DSH 是 **npm 原生安装**（`C:\Users\cloud_user\AppData\Roaming\npm\dsh.cmd`，0.1.7-rc.2），走 `D:\Program Files\nodejs\node.exe` 直接跑 `lib/bin.js web`，**完全不经 WSL**。
- 真实原因：DSH 的启动任务 `n2dshweb` 的 principal 是 **LogonType=Interactive**（只在有交互登录会话时才能跑）。它挂了 Boot 触发器，但开机时没人登录 → 触发器失效；10-24 关机后（10-25 09:46、10:45 两次异常重启）DSH 就再没起来。
- 旁证：`evidence\dshweb.log` 最后一行停在 10-24 06:40（额度报错），任务 LastRun 停在 10-22 08:38 且 result=0x40010004（进程被终止）。

## 二、改了什么

1. **`C:\Users\cloud_user\evidence\runweb.ps1`** 改成幂等启动器（备份 `.bak-20261025`）：
   - 先查 3080 是否在监听，在就 exit 0
   - 日志 >10MB 轮转到 `dshweb.log.old`
   - `DSH_HOME=%USERPROFILE%\.dsh` → `dsh.ps1 web --host 127.0.0.1 --port 3080 --no-open *>> evidence\dshweb.log`
2. **重注册计划任务 `n2dshweb`**（沿用原任务名）：
   - principal：`cloud_user` **S4U**（不需要密码、不需要交互登录），RunLevel Highest
   - 触发器：**AtStartup + AtLogOn + 每 5 分钟**（MultipleInstances=IgnoreNew，ExecutionTimeLimit=PT0S 无限）
   - 效果：开机自启；DSH 崩了进程退出→任务结束→≤5 分钟内下一跳重启
3. 旧机制保持不变：`n2-frpc-dshweb`（SYSTEM，每 5 分钟确保 `frpc-dshweb` 隧道）、`newnode-frpc`（SYSTEM，开机跑 `frpc.toml` 提供 SSH/RDP）。
