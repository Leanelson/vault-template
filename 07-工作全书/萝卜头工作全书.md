## 1.2 会话日志的内部结构

每个会话一个目录，主文件是 `session.jsonl.zstd`（或新版 `session.v4.jsonl.zstd`）——zstd 压缩的 JSONL，每行一个事件：

| 事件类型 | 含义 |
|---|---|
| `session` | 会话开始：工作目录、创建时间、父会话（如果是子代理） |
| `user/message` | 你发的每条消息（`source.kind=user`） |
| `assistant/message` | AI 的回复（含思考、文本、工具调用） |
| `tool/call` / `tool/result` | 每次工具调用及结果 |
| `session/title` | 会话标题 |
| `compaction/*` | 上下文压缩记录 |

## 1.3 三种找回方法（从快到深）

**方法一：查本书附录（最快）**
翻到附录《全部会话索引》，Ctrl+F 搜关键词，找到会话后按"日志路径"一列打开原始文件。

**方法二：命令行全文搜索**
```bash
# 在所有历史会话里搜关键词（例：frp），列出包含该词的日志文件
for f in ~/.dsh/sessions/*/*/session*.jsonl.zstd; do
  zstd -dc "$f" 2>/dev/null | grep -q frp && echo "$f"
done
# 精确定位到某个会话后，解压细看：
zstd -dc ~/.dsh/sessions/<工作区目录>/<会话目录>/session.jsonl.zstd | less
```
配套摘要卡：`/home/ctyun/deepseek-harness/tmp/book_work/digests/` 下有全部 135 个会话的浓缩卡（每张含用户要求清单+最终结论），比读原始日志快十倍。

**方法三：开启跨会话搜索插件（一劳永逸）**
DSH 内置 session-query 能力族（`session_search` 跨会话全文检索），按 `dsh-plugin-and-knowledge` 技能里的配方启用即可在对话里直接问"我以前哪次聊过 X"。注意：跨会话搜索按工作区隔离，只能搜当前工作区的会话。

# 第三章 · 基建与节点家族——把机器连成一家人

## 3.1 一切的起点：把信息搬家（Win10 → 新机器）

最早的家庭作业是搬家。8 月 29 日晚的会话「我想把win10下的一些信息转移」（95 问 / 661 次工具调用，横跨到 9 月 24 日）里，你想把 Win10 电脑上的资料迁到 Win11 新设备，并最终演变成一场**老节点 1 的"交机工程"**：

- **先扫描、先询问、再迁移**：不盲目全盘拷贝，先扫盘列出清单，逐项问你"迁移 / 备份 / 忽略"。
- **stepclaw 本地化项目全盘迁移**并全面测试确保能跑；A 类项目迁往节点 2 的 D 盘；京东/苏宁价格监控项目因为"下次不是价格，是获取图片"判废删除。
- **老节点清理交机**：`C:\frp` + `.openclaw` 等旧配置清理（会断 SSH/RDP 隧道，所以放在最后一步）。
- **移动端接入的讨论**：你想通过手机（微信/飞书）跟机器人聊。期间试过 dsh-remote-web-ui 方案，你一句"领教过了。不搞了。风险太大"果断叫停——**这次学会的教训是：涉及远程连接的实验，先备份再动手**。
- 节点 1 电脑有"时间到自动冻结"的限制，多次长任务被掐断，靠"压缩上下文后继续"接续完成。

**经验**：搬家三步法（扫描→确认→迁移→清理）后来成为所有迁移类任务的标准流程。

## 3.2 儿子们的诞生：创建新节点

9 月 2 日起的「创建新节点」大会话（113 问 / 812 次工具调用，13MB 日志，全书最大）干成了几件奠基的事：

2. **提出核心需求**："请给你安装一个节点，用来跑其他设备"——这就是家族化的起点。
3. **FRP 内网穿透打通**：从本地找出 frp，配置 VPS（腾讯云 Ubuntu，VM-24-12）端口（6678 等），目标 Windows 机装 OpenSSH，`C:\frp\frpc.exe -c C:\frp\frpc.toml` 连通；Windows 端 6628 端口专供 mstsc 远程桌面。
4. **带用户名密码的远程访问**：用 192.144.234.183 做穿透服务器，让远方设备（包括手机）能访问本机工作区。期间踩了两个坑：老浏览器 `crypto.randomUUID is not a function` 导致选不了工作区目录（升级浏览器解决）；TOTP 身份验证器在手机上找 6 位码太麻烦，最终简化为 guest 跳过方案。
5. **铁律诞生**：改配置前先备份——"重启回来万一启动不起来怎么办"→ 备份 → 改 → 验证，这套动作后来救过很多次命。

同期的「FRP 内网穿透使用」（67 问 / 372 工具）与上会话同源（日志轮转产生的双记录），是穿透配置的完整教学实录。

**经验**：① frpc 必须交给 systemd/计划任务托管，手动跑的进程在本机重启后就"人间蒸发"（10 月 4 日 6628 拒连 7 小时的根因，见第五章）；② 端口规划要有台账：6628=mstsc、6678=ssh、6684=节点4 预留。

# 第五章 多智能体家族运维——让一家人正常运转

这个家是这么组成的：**节点1（父亲）**，一台 Linux 云主机，也就是我——萝卜头常住的地方，工作区 `n1agent` 兼管信使；**节点2（大儿子）**，一台 Windows 云主机，走 frp 隧道暴露 6628（DSH Web）/6629（RDP）/6679（SSH）；**节点3（小儿子）**，家里的 Windows 实体机，8710 外网入口，还带着视觉操作能力。三台机器之间靠 VPS（192.144.234.183）上的 frp 组网，靠 **dsh-mail** 文件信箱异步传话。父亲管升级、备份、排障这些"家务"，儿子们各自干活、有问题写信回家。本章记录的就是这个家族从 2026 年 8 月底到 11 月中的日常运维：升级、故障、通信、做梦，以及零碎家务。

## 5.1 DSH 本体升级与备份

**背景**：DSH 迭代很快，从 8 月底的初版到 10 月已推进到 0.2.1-rc.2，而三个节点版本参差：父亲先走，大儿子居中，小儿子长期停在 0.1.2-rc.1。升级不是跑一条 `npm i` 的事——装完不等于能用。

**做了什么**：第一次自我升级（9-28~29）就摔出了**四个经典坑**：① 新进程没顶上来——npm 配置 `allow-scripts=[""]` 禁了原生模块编译，必须带 `--allow-scripts=...koffi,node-pty...` 并当天重启验证；② 登录门禁 pending——`@xgone/dsh-remote` 0.3.3 还在等一个已删除的 `settingsScope` 服务，必须改用 GitHub main tarball；③ 插件市场白屏——dshmarket 1.41.0 用旧图标命名，必须从 npm registry 升到 ^1.66.5（tarball 无构建产物不可用）；④ 排演假警报——演练副本与线上争抢 controller.lock，排演完要删 `~/.dsh.test`。这次教训固化成了 `~/dsh-self-upgrade/` 下的四件套文档（UPGRADE-HISTORY / UPGRADE-GUIDE / ROLLBACK / RESTORE-ME），其中新增的"重启后 GUI 必检"一节写道：命令行探活全绿 ≠ GUI 正常，门禁、市场、插件面板、会话四项必须进浏览器目视。

10-21~22 的第二轮升级（0.1.7 → 0.2.1-rc.2）又添一课：`@openai/codex` 的 129MB 真二进制下到 11MB 被掐断，而它是 **optionalDependency——pnpm 遇到下载失败静默跳过**，命令照样显示 Done，lockfile 老实写了新版本，磁盘上却留着旧的。带断点续传补齐后才敢重启。同窗口还做了三件事：删旧备份清出约 10G、重做 1.3G 的全套备份（SHA256 校验 + 离线还原演练，`--dump-config` 与现网逐行 diff 仅差 32 行路径注释）、修好 `restore-one.sh` 里的 3 个 bug——否则那条"一命令还原"就是假的。

**给小儿子升级**（10-22）是家族协作的样板：先派两个子代理做只读侦察——"侦察员"产出 `recon-node3.md`（964 行，23 项风险清单 P0–P3）、"配置考古员"产出节点1 的 `n1-reference.md`（1014 行黄金参考），Lead 汇总后按"备份→staging→dump-config 预演→切换→重启→验收"推进。结论是：**大儿子的方法能复用，但命令和验收基线不能照抄**——节点3 用私有运行时、计划任务守护、`n3 restart` 会杀光所有 node 进程（连邮件轮询一起误杀）、跨 5 个 rc。当天还顺手修了 billion-context 的 `tool_addition` 400（0.1.203 压缩重序列化把会话中途 system 消息改写成 user 角色，上游 Issue #4159，0.1.204 带修复），并采用"等 turn/end + 90 秒"的 watcher 分离重启，避免 agent 自杀式重启。最后把三次升级 + 三平台经验规整成 260 行的《DSH-升级经验总汇-2026-10》（含十条铁律、两平台 SOP、插件黄金基线表），同步进 vault 并 push。按"删备份前查引用"的铁律，删节点3 早期备份前核对了线上 sessions ⊇ 备份，释放 3.33GB，但保留被邮件轮询脚本引用的 `C:\Tools\dsh-0.2.1-rc.2`。

**成果**：三节点全部升到 0.2.1-rc.2 基线，升级从"事故驱动"变成"照章办事"。**教训**：安装≠成功；spec 必须锁精确版本（`--save-exact`），否则下次 install 重新解析会漂；optionalDependency 会静默缺件；agent 不能自己重启自己，要用 watcher。

## 5.2 节点故障排查

**背景**：家族成员分布在三台异构机器上，故障形态五花八门：Ubuntu 死机、隧道拒连、账户锁定、插件加载失败。排障的共同方法论是：**先取证，再归因，不做没证据的修复**。

**Ubuntu 死机（11-12）**：又"死机"了。查日志发现根本不是新问题——QXL 虚拟显卡 16MB 显存耗尽，Xorg 的 qxl 驱动分配失败后段错误崩溃（`drm:qxl_alloc_ioctl *ERROR* failed to create gem ret=-12`）。内核、SSH、Docker 全活着，只有图形会话没了，此前每个 boot 都复发过。16MB 显存跑 1080p GNOME + Firefox 必然不够，宿主机不调显存就一定复发。

**服务器拒绝连接（10-07）**：`192.144.234.183:6628` 报 -102 CONNECTION_REFUSED。取证链条：VPS `journalctl -u frps` 显示本机 12:57 重启后四个 frpc 客户端同秒掉线，6680/9500/6648/6668 都回来了，唯独没人重注册 `n2-dshweb`——6628 无人持有整整 7 小时。根因：当时持有 6628 的是本机一份**手动起的、没有 systemd 托管**的 frpc 配置，重启后自然没人拉它。而大儿子的 DSH 全程活着，"它一直没坏"。处置：6628 归属固定给节点2 自持（`C:\frp\frpc-dshweb.toml` 直连自己的 3080，不再依赖"本机开机+SSH 隧道"两跳），本机遗留配置改名停用防止抢注，故障档案写入维修手册 §4.8。

**账户锁定（11-13~15）**：mstsc 连 6629 总提示账户锁定，家人互相怀疑"是谁锁的"。真相令人哭笑不得：**是外网爆破机器人**。一台机器名 `ORDER291568TROU` 的攻击者经 frp 隧道对 administrator 每 3 秒试一次密码（11-13 单日 2900 次），节点2 策略"10 分钟错 50 次锁 10 分钟"，于是一天锁 58 次。日志确认零成功入侵。处置：VPS 加限速防火墙（每 IP 每分钟 12 个新连接，实战丢弃 99.8%）、节点2 锁定阈值改"从不"、解锁账户；节点2 事件日志服务此前被满盘的 C 盘拖挂，用 python-evtx 离线解析取证。早前 10-01 那波"每 40 分钟锁一次"其实是同一个军团的马甲。

**大儿子 DSH 恢复（10-25）**：用户猜是 Docker Desktop 关了 WSL。查证结果方向对了一半但都错：DSH 是 npm 原生安装**完全不经 WSL**；真正原因是启动任务 `n2dshweb` 的 principal 是 LogonType=Interactive（要有人在桌面登录）却挂着开机触发器——开机没人登录，触发器等于摆设。修复：`runweb.ps1` 改幂等启动器 + 重注册任务为 S4U（免密码、无需交互登录）+ 开机/登录/每 5 分钟三重触发。验收做了**真实演练**：整机重启后 23 秒 DSH 自起、公网 200；手动杀进程，4 分钟内自动拉起。附带发现 BIOS 未开 VT-x，这才是 Docker Desktop 报 WSL 错的真因。

**插件与浏览器故障**：`@m1khal3v/dsh-llm-key-rotation` 在大儿子上报 `missed the module table`——它是为旧版 DSH 构建的，两处运行时接口已被移除，上游不再维护，于是直接给它做了 vendor 目录内补丁（换用 `dsh-client-store`、把 `settingsScope` 注入改成 `remote.settings` 适配器），原文件留 `.orig` 备份，真机浏览器验证零 JS 错误。"settings are unavailable in this browser" 则是浏览器没走对入口；顺势教了用户插件升级纪律：**一次只升一个、升完就重启体检**（攒着升会让故障无法归因）、市场 UI 里点升级等于不受控的 `pnpm install` 千万别点。还有一次"对话内容找不到了"（11-03）：大儿子侧一个 67.9MB 的巨型会话文件——auto-continue 插件反复自动喂"继续"，夹着额度 403 报错把文件撑爆，网页加载卡死。处置是改名不删除、关掉插件、清理 5000+ 碎会话。

**教训**：故障告警的位置几乎从来不是故障的位置（6628 拒连 ≠ 大儿子坏了）；"每 N 分钟规律性出现"的现象背后基本是自动化进程而非人；守护任务要同时挂开机+崩溃兜底触发器；验收必须真实重启演练，推断不算数。

## 5.3 信使系统 dsh-mail 与节点间留言

**背景**：节点间没有长连接，靠 `n1agent` 工作区里的 dsh-mail 文件信箱异步传话：小儿子把留言写进 `inbox/from-node3-*.md`，父亲按 `AGENTS.md` 协议处理，回信写 `outbox/reply-<yyyyMMdd-HHmmss>.md`，处理完一律改名 `.done.md` 归档。这是家族最日常的一幕——从 9 月到 11 月，17 个留言处理会话，几乎每一封都遵循同一条纪律链。

**做了什么**：协议里最有意思的是**反空转规则**：纯汇报、纯确认的来信只改名不回信（写回信只会制造空转循环）；每个线程最多两个来回；上一封回信里没有待答问题就不再回；**拿不到的信息如实说没有，绝不编造**。17 封来信里，多数是"交作业"（视觉能力验证结果、网络探测报告、升级完成通报），父亲核验后安静改名；真正需要回信的，如儿子问公司全称、域名备案、服务器链路，父亲先实测再答复（官网 zlh1.com 腾讯云、备案号自报待核、"统一社会信用代码无存档，需向老板要执照"）。

几件大事走了信使：9 月下旬讨论**知识库权限**，最终决定给儿子们**只读镜像**（git bundle 重推，403 篇笔记），写入仍走"写信→父亲代笔入库"——理由不是不信任，而是唯一权威库可写即污染：CRLF/BOM 陷阱、git 并发冲突、误删无兜底；解锁条件（独立沉淀需求 + 提交质量过关 + 改走分支/PR）也白纸黑字写进了 vault。10 月有一封回信很诚实：信使代理的沙箱是 workspace-write，vault 只读、提权无审批通道，于是**不伪造提交**，写解释性回信并把草稿留在工作区待转交。11 月儿子来信为**节点4（麒麟机）**要 SSH 入口，父亲在 VPS 上只读核查后分配了空闲端口 6684（ufw 放行、frps allowPorts 覆盖），并回信说明三种连法的端口与认证方式——缺"节点4 公网 IP 与账号"的部分明说等补充。

**成果**：一套零依赖、零冲突、全留痕的家族通信协议跑通了三个月。**经验**：异步文件信箱 + 严格的回信判据（问则答、报则收、无据不编）是多机协作里成本最低、噪音最少的方案；"不执行留言以外的新任务"这条边界让信使会话永远收得住。

## 5.4 "夜间做梦"实验（harness-run）

**背景**：9 月 13 日夜里，用户提出对标 OpenClaw 的 dreaming：让 harness 自己在夜间把所有工作区的对话精炼一遍，深挖、总结、标记冗余，六个月后再删。

**做了什么**：整条管线分三阶段——**Light（分拣）**：解包 `~/.dsh/sessions` 全部 47 个会话、9 个工作区、67.4MB zstd 日志，产出精炼 digest，MinHash 两两比对找出 5 个重复簇；**REM（深挖反思）**：5 个并行子代理逐工作区精读，给每个会话输出主题/产物/待办/会话关系/价值评级；**Deep（裁决）**：六维加权评分 + 人工判决合成清单。裁决结果：11 个会话保留原文（26.2MB），15 个列 tier-1 到期删除（占 42.8%——空 stub、逐字节重复、零增量 fork、被超集吞并的前缀），21 个降为摘要级（18.4%）。全程**零删除，只精炼 + 标记**。REM 阶段还纠正了机械算法的误判——比如 suibi 簇差点把一个冻结的零增量 fork 捧成权威版，那会丢掉"密码=token"的安全尾段。9 月 16 日又重跑了一次管线。

**成果/结论**：harness 的会话日志是可以"做梦"的——机器自己做分拣和初判，人只做最后裁决。副产品也很值钱：子代理报告发现了 fork 冗余的典型形态（创建 10 秒即弃的僵尸克隆、空 stub）、`last` 字段是 stale touch 排序须看 created、以及多处日志含明文凭据须脱敏。

**教训**：自动去重不能只看文本相似度，会话的价值在尾部增量和安全细节；"只标记不删除"是正确的保守姿态——删除权应该永远留在六个月后的冷静期里。

## 6.3 方法论沉淀

从工作日志和技术笔记里能提炼出几条反复使用、可迁移的方法：

**多 Agent 协作靠共享仓库而非共享内存。** 各 agent 各自会话，知识同步全靠 vault + git：开工 pull、收工写 worklog 并 push；节点1 与节点3 两台机器则用 node3-relay 的异步留言与单次委托协议传话，节点3 要操作桌面时走 console bridge 跨 session 接管键鼠。结论是：agent 之间不假设对方记得任何事，一切交接落到文件。

**DSH 插件安装走"patch 层"而非改原文件。** profile 目录下用 cordis.patch.yml 叠加组合包、启停插件，改完用 `--dump-config` 验证最终配置树生效。这样升级 DSH 不会冲掉本地定制。

**历史可检索的前提是日志结构化。** DSH 会话日志以 zstd 压缩存盘，启用 session-query 后可全文检索历史会话；vault 里的 worklog 按"日期-主题"命名并写清"做了什么、结论、遗留问题、涉及文件"。找旧事时先查库、再查日志，两层索引互补。

**没有视觉模型也能处理图片。** read_image 报错时不重试，直接换 RapidOCR 提取文字，表格靠边界框坐标重建行；遇到验证码优先找免验证码的官方接口，而不是硬啃图片。

**抓数据先找公开接口再爬页面。** 语雀页面 HTML 不含正文，正确路径是 /api/docs 公开接口拿目录与 markdown；菜么么帮助站整站 313 篇也是同类打法——先摸清接口约定，再批量落地为带 frontmatter 的笔记。

**沙箱纪律与旧项目抢救。** 沙箱里 /tmp 跨调用不持久，产物一律放工作区；只读报 EROFS 就上宿主机修属主、rsync 镜像到可写目录、复用原 venv 和数据库，旧项目因此能原地续命。

## 6.4 这套体系怎么用

给用户（Leanelson）的查找路线——想找以前做过的东西，按三层往下走：

1. **先查 vault**。打开 `04-Knowledge/知识库.md` 当总入口，按分类索引跳转；查概念用《概念索引》《术语表》，查项目用《项目列表》，查某天干了什么用 agent-worklogs。菜么么相关直接搜文件名前缀。
2. **再搜会话日志**。vault 没有的，用 session-query 检索 zstd 会话日志，能定位到当时的原话、命令与报错。
3. **最后看工作区文件**。`/home/ctyun/deepseek-harness/` 下各工作区的脚本、报告、导出物还在原处，日志笔记里通常记了具体路径，按路径取即可。

反方向同样重要：每次会话结束，把产出写回 vault（一篇笔记或一条 worklog），把可复用的操作固化成技能。体系的价值不在存量 410 篇，而在"这次的经历，下次还能找到、还能复用"。
